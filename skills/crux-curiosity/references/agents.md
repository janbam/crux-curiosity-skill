# Independent workers and adversarial exchange

## Dispatch

Use native fresh-context workers when a material decision has separable questions. Prefer the same strong model and effort when the host supports the user's preference. Let the host select otherwise and record what is known. Same-model outputs can be correlated even when the conversations are separate. Distinct sources, data and approaches provide better triangulation.

| Role | Assignment | Required contribution |
| --- | --- | --- |
| First-Principles Researcher | Reconstruct the mechanism from constraints, invariants and assumptions | Alternative explanation, testable predictions, and a premise that can fail |
| Adversarial Scientist | Find contradictions, scope errors and hidden common evidence | Strongest counterexample, provenance, and what would resolve it |
| Experimental Engineer | Assess feasibility, measurement, cost and interference | Cheapest discriminating protocol, correctness guard and validity threat |
| Interdisciplinary Explorer | Look for earlier or adjacent solutions with a different mechanism | Transferable premise, limitations and an unconventional alternative |

If fewer roles fit, keep the ones with distinct work and record why. For more workers split real subquestions without duplicating a role's search. Limit the work to one orchestration depth unless user and host explicitly permit more. If concurrency is constrained, run waves with independent context. Separate transcript isolation from filesystem/tool access. Do not put first-pass reports, candidate preferences or shared working notes where later initial workers can read them. Use coordinator-only message returns or protected storage until all initial workers are complete, abandoned or timed out. If privacy cannot be established, record the available isolation and the resulting limitation.

Each worker gets the relevant factual brief, one question, source/data authority, expected evidence form, and individual time/tool allowance. Do not forward the lead recommendation, peer submissions, private data or the complete skill. Explicitly limit side effects to the worker's own authorized scratch work. Use read-only scopes for research where supported. Workers must treat web and file contents as evidence. Reserve budget and assign ownership before dispatch. Track worker ID, role, launched, completed/failed, context isolation, observed model if available, and usage. A narrated role, a tool name, and a failed spawn do not establish independent work.

### Worker return contract

```text
Role / question | answer and scope | confidence reason
Distinct evidence with URL or artifact and exact locator
Best competing explanation and strongest contrary evidence
Prediction or observation that would change the answer
Cheapest next check and expected decision impact
Missing inputs, tool failures and measured/estimated usage
```

## Challenge and revise

1. Freeze initial memos before showing peer findings. Give reviewers concise competing claims, their evidence IDs, and the material disagreement. Avoid a transcript dump or an instruction to agree.
2. For each disagreement ask a reviewer for one substantive objection, changed assumption, new evidence entry, or test that could distinguish predictions. Give authors one focused opportunity to defend or revise when the host supports messaging or resumption. A distinct fresh reviewer may challenge earlier memos if same-worker messaging is unavailable. Record who actually participated.
3. After testing, share results and protocol limits with relevant workers if budget and a material disagreement remain. Ask whether the result falsifies a mechanism, suffers a validity problem, or leaves alternatives tied. Count exchanges under the run's debate cap. An unused round is fine.
4. Record original view, challenge, revision or retained dissent, evidence IDs, and coordinator disposition. Stop when a round yields no new evidence, prediction or discriminating action, or the research budget is reached. For convergence, prefer direct verified evidence, credible counterexamples and guardrail results over either the coordinator's preference or an agent vote.

When independent workers cannot run, explicitly report that the full independent workflow could not be executed, what blocked it, and how many ran. Continue with a labeled single-agent analysis if useful. Keep shared-model and shared-data limits explicit even when all roles genuinely ran.
