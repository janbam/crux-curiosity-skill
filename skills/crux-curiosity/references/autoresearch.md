# Bounded autoresearch

Begin only with an authorized isolated or reversible editable scope, a stable decision-relevant metric, deterministic correctness or substantive guardrails, a baseline and explicit trial/time bounds. Budget for confirmation and fresh validation before tuning. Protect the evaluator, inputs, guards, timeouts, permissions and budget from candidate changes. For unsafe, unverifiable or qualitative goals use the research and decision path instead.

## Contract

Freeze baseline revision, incumbent, evaluator/data revisions, metric direction and practical difference, noise handling, guards, per-trial limits, allowed edit surface, retained state policy and stop rules. Choose representative search inputs and separate independent final validation when practical. With adversarial candidates, enforce evaluator and holdout isolation externally or decline the unsafe trial. Prefer a hidden evaluation boundary and minimal return of holdout feedback. If cases are readable in the candidate environment, describe any final check as out-of-sample with visible cases, or tuning if already used.

The decision threshold must handle noise proportional to the stakes. Examples include repeated matched sign and magnitude, a paired interval excluding the practical threshold, or an exact deterministic bound. Record the choice before seeing results. A search leader is provisional until required confirmation and validation support the recommendation.

## Iteration

1. Inspect the current best measured result, guard failures, bottleneck and tried ideas. Propose a specific change and measurable prediction. Prefer a high-value small change, occasionally sampling an alternative mechanism when the local neighborhood saturates.
2. Reserve remaining budget and record a pending trial against a stable revision. Make one scoped change in a disposable copy, isolated worktree or host sandbox. Bound execution, run correctness and measurements with the same protocol, and record status, raw results, environmental factors and usage.
3. Compare against the incumbent and preserve the starting baseline. Check noise, magnitude, guards and evaluator integrity. A failed guard or nonmaterial/noisy difference receives reject or inconclusive. Retain a search improvement only when its frozen rule passes. Keep a complete result before updating the authoritative checkpoint. Restore only your own scoped unsuccessful change or discard its isolated copy. Preserve negative results.
4. Deduplicate the next proposal against trial history. Update expected gain, resource use, current best and remaining validation reserve. Try a different mechanism when the plateau threshold is reached and an informative branch fits. Avoid widening the scope in reaction to a failed result.
5. At convergence freeze the selected revision. Run reserved independent validation within the separate boundary if available. If validation fails or is inconclusive, preserve the previous verified solution or original baseline and report the tuning result separately. Once results inform tuning, replace those validation cases for future independent confirmation.

Record a stop reason when a verified target is met, a meaningful gain is no longer likely, a hard limit is reached, an admissible branch no longer fits, no safe measurement exists, or a required capability fails. An optimizer cannot change the rules that declare its success. Stop a provisional search winner when no further authorized confirmation fits and label its status explicitly.

Trial history should link attempt ID, parent and candidate revisions, hypothesis, protocol and result, raw paths, guard checks, costs, retain/reject/inconclusive/invalid status and recovery action. Parallel variants need separate edit scopes, accounting and resource isolation. Single-writer checkpointing and an explicit pending attempt allow recovery. See [operations](operations.md#resume-and-recovery).
